# 固定按钮 / 桌面层 行为规范（v1.3）

> 这份文档回答一个问题：**卡片右上角那颗图钉，到底做了什么？**
> 以及它背后那套「钉桌面层」的机制，在什么机器上会退化成什么样子。

---

## 1. 三个动作的准确定义

| 动作 | 主进程做了什么 | 你看到的效果 |
| :-- | :-- | :-- |
| **点「固定」** | 按桌面层策略把窗口 `SetParent` 到桌面层窗口（WorkerW / Progman），或压到「桌面图标之上、普通窗口之下」；同时 `setMovable(false)`，并且**拦掉所有拖动 IPC** | 卡片躺在桌面上，被任何窗口盖住，**拖不动**；托盘里显示「已固定」 |
| **点「解锁」** | `SetParent(hwnd, NULL)` 解绑 → 回到普通顶层窗口；`setMovable(true)`，放行拖动 IPC | 卡片仍待在原位，**可以拖**；拖动过程中会浮到最上层（不然会被别的窗口挡住，看不见自己在拖什么），松手后重新沉回桌面 |
| **再点「固定」** | 用**当前**位置重新钉一遍（`GetWindowRect` 取当前物理矩形 → 钉完 `SetWindowPos` 原地复核） | 锁在**新位置**，而不是解锁前的老位置 |

要点：

- **固定 = 真的钉层**，不是为了好看只改 UI；解锁 = 真的解绑。这两件事由 `store.locked` 一个字段驱动，组件卡片和设置页里的「固定状态」勾选框、托盘菜单是**同一条代码路径**（`toggleLock()` → `applyLayer()`）。
- **锁定的权威判定在主进程**。渲染层那句 `if (state.locked) return` 只是省一次 IPC；就算渲染层状态过期，主进程 `drag:start/move` 也会拒掉（写日志 `drag:start 被拒：已固定`）。
- 位置**只在解锁态**会被拖动改变；配置里存的坐标永远是**屏幕坐标（DIP）**。

## 2. 桌面层四级策略（`desktopLayer` 偏好）

偏好只是「首选」，真实生效层级看自检结果。`auto` 会按下面的顺序**逐级回退**：

| 层级 | 做法 | 特点 |
| :-- | :-- | :-- |
| `workerw` | `SetParent` 到壁纸层 WorkerW | 最强：被所有窗口盖住、不进任务栏/Alt+Tab，`Win+D` 也不消失 |
| `progman` | `SetParent` 到桌面窗口 Progman | 语义同上，部分机器命中测试更宽松 |
| `sink` | 不挂父窗口，`SetWindowPos(hwnd, 桌面图标层, SWP_NOMOVE\|SWP_NOSIZE)` | **一定可点击**，被其它窗口盖住；2 秒一次的 keeper 守着 z 序 |
| `normal` | 完全不动层级 | 兜底，保证组件永远能用 |

- 偏好 `auto` = `workerw → progman → sink → normal`
- 偏好 `workerw` = `workerw → sink → normal`（跳过 Progman）
- 偏好 `bottom` = `sink → normal`（兼容模式）
- 偏好 `normal` = 只有 `normal`

`WorkerW` 的坑（很多同类软件栽在这）：**挂到壁纸层的窗口通常收不到鼠标点击**——点击命中的是盖在上面的桌面图标层（`SHELLDLL_DefView` / `SysListView32`）。如果强行钉上去，卡片上的按钮就全点不动了。所以本项目的做法是：**钉完立刻自检，点不到就自动退到下一级**。

---

## 3. 点击自检（`probeHitTest`）

钉层之后马上做一次：

```
GetWindowRect(自己的 HWND) → 取窗口中心点
WindowFromPoint(那个点)    → 问一句「这个点上鼠标点得到谁？」
命中 == 自己（或自己的子窗口）→ 通过
命中 == 别人（桌面图标层等）  → 这一级不合格，退下一级
```

- 探测本身没做成（非 Windows / 窗口当时是隐藏的 / FFI 报错）**按通过处理**，不会因为探测失败把好方案毙掉。
- 自检结论会写进日志和「关于」对话框（`点击自检：ok / hit-other / unknown:*`）。
- 想绕过自检、强行钉死壁纸层：托盘 → 桌面层 → **强制壁纸层 WorkerW（跳过自检）**，或把 `layerProbe` 置为 `false`。
- 想现场看到每一级的结果：托盘 → **桌面层自检…**（会依次试 4 级并把结论列出来）。

## 4. 两个守卫

| 守卫 | 周期 | 干什么 |
| :-- | :-- | :-- |
| `layerKeeper` | 2s | `sink` 模式下把窗口压回「桌面图标层之上」，不让它被挤开 |
| `layerWatchdog` | 4s | 钉在 WorkerW/Progman 时，比对 `GetParent(hwnd)` 是否还是当初那个句柄；Explorer 重启 / 掉层了就自动重钉一遍（重钉时会重新自检） |

另外：窗口位置每次启动都会做一次**可见性兜底**——若上次的位置已经跑到所有屏幕之外（换了显示器 / 改了分辨率），自动拉回主屏右下角。

## 6. 还没在真机上验证的事（需要你确认）

自动化能覆盖的是**逻辑**（Tests 里 9~15 组用例跑的就是「真钉 / 真解绑 / 钉新位置 / 点不到就回退」），下面这些必须真机看：

1. **壁纸层的点击自检到底过不过**：这条取决于你机器的 Explorer 版本和是否装了桌面美化工具。三种可能的结果都在设计里兜住了：
   - 过 → 固定后真的在壁纸层，被所有窗口盖住；
   - 不过 → 自动落到兼容模式（桌面之上、可点击），你只会看到日志 + 关于里写着 `probe=hit-other`，功能不受影响；
   - 全部不过 → 普通窗口兜底。
2. **双击/单击触发**：卡片的双击 = 打开设置；锁定态下点击卡片不应有任何位移。
3. **透明窗口的命中测试**：卡片四周有 20px 阴影留白，正常现象是这一圈"点不到"（不影响使用）。

## 7. 排障

| 现象 | 怎么办 |
| :-- | :-- |
| 固定后按钮点不动 | 托盘 → 桌面层自检…，看 Wallpaper 那行是不是 ❌；是的话把「桌面层」改成 **兼容模式**，或关掉「钉层前做点击自检」并手动选兼容模式 |
| 解锁了还是拖不动 | 看日志里 `drag:start 被拒` 是不是还在刷；有的话说明托盘/设置里的「固定状态」还是勾上的，取消勾选 |
| 拖完松手位置跳了一下 | 拖动结束会重新落位（`drag:end` → `applyLayer()`），位置取的是松手时的屏幕坐标；如果跳得很远，把日志发我 |
| 重启后跑回老位置 | 看 `位置兜底` 日志；拖动结束落盘有 400ms 防抖，**松手后立刻关机**可能丢掉最后一次位置 |
